# Held-out baseline and retrieval experiment

The 32 questions, criteria, expected answers and 69 supporting passages were authored by Codex before running the answering model. They use the existing frozen 20260925 Comprehensive Rules and card corpus. No expected answers or rubric fields are passed to inference. This is an AI-authored evaluation, not independent human validation. Once baseline answers are inspected, these cases become regression data; later scores must not be described as held-out accuracy.

Baseline: existing vector-free implementation, seed 42, Qwen 3.8 27B Q4_K_M, medium reasoning, temperature 0.1, output limit 3500, loaded context 8192. Preserve all answers, sources, failures and review notes. Review each criterion and unsupported claims manually with AI assistance against the frozen passages. Citation support is a separate reviewed field: all cited claims must be supported by the cited excerpts; clarification-only responses need no citations. Appropriate clarification is not abstention.

After baseline, classify failures as retrieval, packing, reasoning, clarification or presentation. Make each substantive fix a separate implementation commit, followed by both suite runs and a results commit. Do not change criteria after seeing answers. Any discovered rubric defect needs an explicit addendum rather than silently changing historical grades.

Vector experiment: keep generation settings and corpus fixed. Embed rule passages locally using the installed Nomic Embed Text v1.5; preserve exact Oracle attachment lookup. Compare hybrid lexical/semantic retrieval with the latest lexical configuration on BOTH suites at seed 42. Store model/index identity and measure index size/build time, retrieval time, end-to-end latency, correctness, unsupported claims and citation support. No benchmark labels are used to build the index.

Adoption gate: hybrid must improve correct-and-complete answers on the 52-case combined set, introduce no new unsupported answers, and keep median end-to-end latency within 20% of lexical on each suite. A passing result requires another matched seed before enabling it by default. If it fails, retain the experimental option with lexical as default and document the tradeoff. Single runs are descriptive, not statistical proof. Do not tune embeddings to these labels during this experiment.

## Reviewed prompt experiment

The source-quotation response contract was committed and measured on both frozen suites. It remained 25/32 on held-out and 20/20 on original, improved citation-support reviews 10→9, but produced new unsupported details and increased held-out p95 from 18.79s to 28.99s. It was reverted; artifacts and comparison are retained under `results/source-quotes-*`.

## First hybrid result and targeted follow-up

The first hybrid run (RRF k=60, 24 semantic candidates, 64-rule cap) improved the held-out set to 29/32 but regressed the original suite to 19/20. In both suites it newly claimed a 0/0 indestructible creature with no damage survives. Candidate sources contained CR 704.5g but omitted adjacent CR 704.5f, which governs zero toughness. The run therefore fails the no-new-unsupported-answers gate and hybrid is not enabled by default. The follow-up keeps the original ranked top 64 intact, then appends up to 32 lettered clauses sharing a numbered parent (or immediate neighbors for unusually large families). This preserves the lexical/semantic ranking while including nearby exceptions. Historical first-run artifacts remain immutable.

A second hybrid iteration placed immediate siblings directly into the ranked list before applying the 64-candidate cap. It reduced held-out accuracy 29/32→28/32 and displaced CR 701.14 from the fight question, causing a new double-strike/fight error. The original remained 19/20 with the zero-toughness error. This iteration is also rejected. A third committed implementation retains the original top-ranked candidate set intact and appends complete lettered families afterward, up to a total of 96 rules. It is evaluated against both frozen baselines; see the resulting experiment report.

## Candidate-family expansion result

The first neighborhood follow-up expanded siblings inside the 64-candidate cap; it displaced core rules and reduced held-out accuracy to 28/32. The next version preserved the first 64 fused primary candidates and appended up to 32 same-parent lettered clauses. This completed candidate list still failed the context-budget test: expanded siblings from earlier rule groups consumed prompt room before later primary candidates. On the held-out suite it scored 28/32 versus 29/32 for the preceding hybrid and 25/32 for lexical; on the original suite it scored 19/20 versus 19/20 hybrid and 20/20 lexical. CR 704.5f was still omitted from the packed context, and the 0/0 unsupported answer remained. The fight/double-strike answer also regressed on heldout. The approach is rejected. The next implementation preserves every lexical candidate in its exact order and appends up to 24 vector-only candidates. This protects lexical coverage, but the context packer may still omit evidence; the full two-suite run determines whether the change is useful.

## Lexical-preserving hybrid result and replication gate

The next implementation retains the complete structural lexical candidate list in its original order, then appends up to 24 semantic-only candidates. The packer handles semantic-only rules after lexical evidence. At seed 42 it scored 28/32 on heldout (lexical 25/32) and 20/20 on the original suite (lexical 20/20), for 48/52 combined versus 45/52 lexical. Unsupported answers fell from five to one on heldout and zero on the original suite; case-by-case review found no new unsupported answer. Median latency rose 0.4% and 4.5%, within the predeclared 20% limit. There were no errors or truncations. This passes the seed-42 gate but does not establish reliability. Run both lexical suites and both hybrid suites at seed 43; only enable hybrid by default if the matched replication also passes the predeclared criteria.
